## 一、软件概述

### 1.1 软件简介

HodoopForge 是一款企业级Hadoop集群部署与管理平台软件，专为解决 Apache Ambari 3.x 与 Apache Bigtop 3.5.0及以上版本之间联调困难、兼容性差、部署复杂等问题而开发。

### 1.2 主要功能

- 一键式/向导式集群部署
- 多节点Docker容器化部署
- 本地YUM仓库自动构建
- Ambari 3.1.0与Bigtop 3.5.0深度集成
- 支持15+大数据组件
- 服务健康监控与告警
- 兼容性自动修复

### 1.3 支持的组件

| 组件 | 版本 | 功能 |
|-----|------|-----|
| Hadoop | 3.3.6 | 分布式存储与计算 |
| HBase | 2.6.2 | 分布式列式数据库 |
| Hive | 4.0.1 | 数据仓库 |
| Spark | 3.5.6 | 内存计算框架 |
| Kafka | 3.4.1 | 消息队列 |
| ZooKeeper | 3.8.4 | 协调服务 |
| Ranger | 2.7.0 | 安全管理 |
| Flink | 1.20.1 | 流处理框架 |

## 三、安装部署

### 3.1 获取软件

从项目仓库获取软件包：

```bash
git clone https://github.com/starkernel/otowyue_ops_hadoop.git
cd otowyue_ops_hadoop
```

### 3.2 目录结构

```
otowyue_ops_hadoop/
├── ambari3/                    # 主部署目录
│   ├── ambari-repo/           # 本地仓库目录
│   ├── conf/                  # 配置文件
│   ├── scripts/               # 部署脚本
│   └── docker-compose.yml     # 容器编排配置
├── ambarirpm/                  # Ambari RPM包
├── bigtoprpm/                  # Bigtop RPM包
└── copyright_docs/             # 著作权申请材料
```

### 3.3 部署步骤

#### 步骤1：启动Docker容器

```bash
cd ambari3
docker compose up -d
```

执行后，系统将启动4个Docker容器：
- bigtop_hostname0（主节点，运行Ambari Server）
- bigtop_hostname1（从节点）
- bigtop_hostname2（从节点）
- bigtop_hostname3（从节点）

#### 步骤2：初始化节点环境

```bash
cd scripts
./setup.sh
```

此脚本将完成：
- 安装必要软件包（sudo、openssh、wget等）
- 配置SSH免密登录
- 启动sshd服务
- 分发SSH公钥到所有节点

#### 步骤3：构建本地YUM仓库

```bash
./setup-ambari-repo.sh
```

此脚本将完成：
- 复制RPM包到仓库目录
- 创建YUM仓库元数据
- 启动Nginx提供HTTP服务

#### 步骤4：安装Ambari Server

```bash
./install-ambari-server.sh
```

此脚本将完成：
- 安装Ambari Server RPM包
- 安装并配置MySQL数据库
- 初始化Ambari数据库schema
- 注入Bigtop 3.5.0 Stack定义
- 启动Ambari Server服务

#### 步骤5：安装Ambari Agent

```bash
./install-ambari-agent.sh
```

此脚本将在所有节点安装并启动Ambari Agent。

## 四、系统配置

### 4.1 访问Web界面

部署完成后，通过浏览器访问：

```
http://localhost:20609
```

默认登录凭据：
- 用户名：admin
- 密码：admin

### 4.2 创建集群

#### 4.2.1 启动安装向导

1. 登录Ambari Web界面
2. 点击"Launch Install Wizard"
3. 输入集群名称

#### 4.2.2 选择Stack

1. 在Stack选择页面，选择**BIGTOP 3.5.0**
2. 确认组件列表

#### 4.2.3 配置仓库

选择"Use Local Repository"，配置如下：

| 仓库类型 | Base URL |
|---------|----------|
| BIGTOP-3.5.0 | http://bigtop-hostname0.bigtop.apache.org |

OS类型选择：redhat8

#### 4.2.4 注册主机

在目标主机输入框中填入：

```
bigtop-hostname0.bigtop.apache.org
bigtop-hostname1.bigtop.apache.org
bigtop-hostname2.bigtop.apache.org
bigtop-hostname3.bigtop.apache.org
```

SSH私钥：使用默认的id_rsa

#### 4.2.5 选择服务

根据需求选择要安装的服务，推荐基础配置：
- HDFS
- YARN + MapReduce2
- ZooKeeper
- Hive
- HBase（可选）
- Spark（可选）

#### 4.2.6 分配Master

系统自动分配Master组件到各节点，可手动调整。

#### 4.2.7 分配Slaves和Clients

系统自动分配Slave和Client组件。

#### 4.2.8 自定义配置

根据提示配置各项服务参数，使用默认值即可。

#### 4.2.9 审核

确认配置无误后，点击"Deploy"开始部署。

## 六、集群管理

### 6.1 添加服务

1. 点击左侧"Actions" → "Add Service"
2. 选择要添加的服务
3. 按向导完成配置和部署

### 6.2 删除服务

1. 选择要删除的服务
2. 点击"Service Actions" → "Delete Service"
3. 确认删除

### 6.3 扩容集群

1. 准备新节点（运行Docker容器）
2. 在Ambari中选择"Actions" → "Add Hosts"
3. 按向导完成新节点注册和组件部署

### 6.4 高可用配置

#### 6.4.1 NameNode HA

1. 选择HDFS服务
2. 点击"Service Actions" → "Enable NameNode HA"
3. 按向导配置JournalNode和ZKFC

#### 6.4.2 ResourceManager HA

1. 选择YARN服务
2. 点击"Service Actions" → "Enable ResourceManager HA"
3. 配置备用ResourceManager

## 七、故障排除

### 7.1 Hive服务问题

#### 问题现象
Hive Metastore或HiveServer2无法启动，或告警显示连接失败。

#### 解决方法

运行修复脚本：

```bash
cd ambari3/scripts
./fix-hive.sh
```

然后在Ambari UI中重启Hive服务。

#### 问题原因
Hive 4.0.1与Ambari 3.1.0存在兼容性问题：
1. hive.exec.post.hooks配置值异常
2. hive_check.py认证参数大小写问题
3. Metastore schema未初始化

### 7.2 容器重启后主机名丢失

#### 问题现象

容器重启后 IP 重新分配，/etc/hosts 中的旧记录导致各节点无法相互解析，Ambari 显示 Agent 失联、服务无法启动。

#### 解决方法

> **⚠️ 先判定"重启"还是"重建"**：以下命令仅适用**重启（restart）**——软件层（Ambari/Hadoop/MySQL）仍存在，只是 hosts/软链接/包名被还原。若容器被**重建（recreate）**（典型诱因：清理网段冲突执行过 `docker network rm <网络名>` 后再 `docker compose up -d`），可写层已清空、软件全部丢失，运行该命令会因目录不存在报错，**必须执行第三章全量安装步骤**。

```bash
# 0. 确认可写层还存在（而非被重建清空）
cd ambari3
docker compose exec bigtop_hostname0 bash -c \
  'test -d /usr/lib/ambari-server && echo KEEP=重启 || echo WIPED=重建'

# 1. 重启容器（配置无变化时应使用 restart，避免 up -d 误触发重建丢层）
docker compose restart

# 2. 修复 hosts/软链接/包名
cd ambari3/scripts
./setup-hostname.sh

# 3. 启动 Ambari Server 与所有 Agent，再在 Web 界面（http://localhost:20609）Start All
```

若第 0 步输出 `WIPED=重建`，说明容器已被重建，需按 **第三章 3.2 部署步骤** 全量重装（启动容器→初始化节点→构建仓库→安装 Server→安装 Agent→Web 界面创建集群），并在 Deploy 失败时使用修复模块（`post-deploy-fixes.sh`）反复修复直至成功。

#### 注意事项

- 日常重启一律使用 `docker compose restart`（保留可写层）；`docker compose up -d` 在容器配置、镜像或网络与 compose 定义不一致时会执行重建（可写层清零）。
- 脚本遵循幂等设计：`setup.sh`、`install-ambari-server.sh`、`install-ambari-agent.sh`、`post-deploy-fixes.sh` 均可重复执行而不破坏已装环境。

### 7.3 Ambari Agent无法连接Server

#### 检查步骤

1. 确认Ambari Server正在运行
2. 检查网络连通性
3. 检查/etc/hosts配置
4. 检查防火墙设置

### 7.4 服务启动超时

#### 解决方法

1. 检查服务日志
2. 增加启动超时时间
3. 检查资源是否充足
